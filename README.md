# 🧭 OrgTrace — ИИ-агент анализа организационной структуры и функционала

> HackAlem AI · Кейс 1. Агент, который не верит на слово: каждый вывод подтверждён цитатой
> из исходного документа, а цитаты сверяются кодом, а не моделью.

## 1. Название проекта

**OrgTrace** — прослеживаемое сравнение организационных документов «до» и «после» реорганизации.

## 2. Краткое описание

При реорганизации эксперту приходится вручную сопоставлять положения и приложения, чтобы найти
потерянные, дублирующиеся функции и конфликты интересов. OrgTrace сравнивает две редакции
документа и формирует аналитическое заключение, в котором у каждого вывода указаны документ,
пункт, страница и дословная цитата.

**Пользователь:** сотрудник подразделения, который анализирует организационные изменения.

## 3. Что реализовано

- Разбор PDF, DOCX и XLSX на пункты с номером страницы. Учтены склеенные пункты
  («…Общества. 3.10.Работники…»), подпункты «а., б.», номера страниц и оглавление.
- Извлечение оргструктуры из пункта «…состоит из следующих структурных подразделений», должностей
  и подчинённости. Закрепление функций раздела 5 за подразделениями по заголовкам вида
  «5.4. Директор департамента …:».
- **Must have 1.** Определение созданных, сохранённых, реорганизованных и упразднённых
  подразделений (`StructComparator`).
- **Must have 2.** Выявление потерь, частичных потерь (с указанием утраченного фрагмента текста),
  переносов функций и устранённого дублирования (`LossDetector`).
- **Must have 3.** Дублирование функций (`DuplicationDetector`, типовые обязанности руководителей
  отфильтрованы) и конфликты интересов (`ConflictDetector`: перекрёстное подчинение,
  самопроверка «консультирование + мониторинг», управленческие роли в подконтрольных обществах).
- **Must have 4.** Прослеживаемость: у каждого вывода есть `doc_id`, пункт, страница и цитата.
  `CitationVerifier` проверяет полное дословное вхождение, `CitationRepair` исправляет
  страницу только существующей цитаты (до 2 попыток). Неподтверждённые выводы выносятся отдельно.
- **Must have 5.** Аналитическое заключение в Markdown и JSON, интерфейс Streamlit с вкладками.
- Дополнительно: битые перекрёстные ссылки после перенумерации, пустые пункты, упоминания
  должностей, которых нет в структуре.
- Необязательный LLM-слой (при наличии `OPENAI_API_KEY`): LLM-судья для пограничных случаев
  потери и дублирования, чат с агентом через Function Calling
  (инструменты `search_clauses`, `get_clause`, `list_findings`).

## 4. Как работает решение

1. Пользователь загружает документ «ДО» и документ «ПОСЛЕ» (или нажимает «Демо»).
2. Агент на LangGraph проходит шаги:
   `parse → plan → structure → struct_compare → loss → duplication → conflict → crossref →
   [llm_review] → verify ⇄ repair → report`.
   AI-режим выбирается явно; по умолчанию используется детерминированный режим. Планировщик решает, какие инструменты применимы к загруженным документам, а верификатор
   возвращает неподтверждённые выводы на исправление.
3. Интерфейс показывает ход агента, метрики, выводы по вкладкам с цитатами «было / стало»
   и отчёт для скачивания в Markdown и JSON.

## 5. Технологии

Python 3.11, FastAPI, Streamlit, LangGraph, Pydantic v2, PyMuPDF, python-docx, openpyxl,
scikit-learn (TF-IDF), rapidfuzz, numpy, pytest. Необязательно: OpenAI API (`gpt-4o`,
`text-embedding-3-small`) — модели задаются через переменные окружения.

## 6. Архитектура

```mermaid
flowchart LR
  U[PDF / DOCX / XLSX] --> P[Parser: пункты + страницы]
  P --> PL[Planner]
  PL --> S[extract_units + assign_owners]
  S --> SC[StructComparator]
  SC --> LD[LossDetector]
  LD --> DD[DuplicationDetector]
  DD --> CD[ConflictDetector]
  CD --> XR[CrossRefChecker + DefectDetector]
  XR -->|есть ключ| LLM[LLM review]
  XR --> V[CitationVerifier]
  LLM --> V
  V -->|ошибки, попыток < 2| R[CitationRepair]
  R --> V
  V --> REP[ReportGenerator: JSON + Markdown]
```

## 7. Установка и запуск

```bash
git clone <URL_РЕПОЗИТОРИЯ> && cd orgtrace
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # ключ OpenAI необязателен
streamlit run ui/app.py         # интерфейс: http://localhost:8501
uvicorn app.main:app --port 8000   # API и Swagger: http://localhost:8000/docs
```

Через Docker: `docker compose up --build`. Команды `make test`, `make ui`, `make api`,
`make demo` делают то же самое короче.

## 8. Как проверить решение

```bash
pytest -q          # парсер, золотой набор, цитаты, API, кэш, LLM-контракты и UI

                  data/samples/polozhenie_red09_protocol7.pdf --out report
```

## 9. Данные и интеграции

- Контрольный комплект организатора: `data/samples/` (Положение о внутреннем аудите,
  ред. 8 — протокол № 13; ред. 9 — протокол № 7).
- OpenAI API — только при заданном `OPENAI_API_KEY`. Без ключа внешних обращений нет.
- Результаты запусков сохраняются в `runs/`, эмбеддинги OpenAI кэшируются в `.cache/`.

## 10. Ограничения

- Выводы рекомендательные и требуют проверки ответственным сотрудником.
- Сравнивается один основной документ «до» и один «после».
- Структура извлекается из текстовых положений; схемы-картинки не распознаются (OCR нет).
- В DOCX нет страниц: вместо номера страницы используется условный блок из 40 абзацев.
- Пороги сходства откалиброваны на контрольном комплекте; на других документах
  их нужно проверить.
- Сопоставление с законодательством и бенчмаркинг с другими операторами не реализованы.
- В LLM-режиме модель может переклассифицировать пограничные случаи; золотые тесты
  фиксируют детерминированный режим. LLM-путь проверяется на имитации клиента OpenAI.
- Чат требует настроенного ключа. Источники новых запусков, включая кэш, сохраняются в SQLite.

## Обновление анализа и интерфейса

Интерфейс разделён на три шага: загрузка документов, выбор режима, результаты. Карточки
метрик фильтруют выводы. Доступны поиск по цитатам и подразделениям, фильтр критичности,
двухпанельное сравнение полных пунктов с подсветкой удалений, добавлений и замен,
выгрузка отчётов, история текущей сессии и чат с проверкой дословных цитат.

### Воспроизводимый запуск

Обычный запуск API, CLI и демо использует **deterministic**: правила + TF-IDF без внешних
обращений, даже если в `.env` есть ключ. AI-проверка включается явно в интерфейсе,
через `--mode llm` в CLI или multipart-поле `mode=llm` в `POST /api/analyze`.
Для API демо: `POST /api/analyze/demo?mode=llm`. Требуются `OPENAI_API_KEY` и `USE_LLM=1`.

Вызовы LLM используют temperature=0, строгую JSON Schema и локальную Pydantic-валидацию.
Однако temperature=0 сам по себе не гарантирует повторяемость облачной модели. Повторяемость
повторного анализа обеспечивается сохранением результата в `CACHE_DIR/orgtrace.sqlite3`
(по умолчанию `.cache/orgtrace.sqlite3`). Ключ учитывает SHA-256 обоих файлов **в порядке
до/после**, форматы, режим, модели, версии библиотек и хеш кода алгоритма/промптов.
Переименование файлов не вызывает повторного анализа: отчёт хранит исходные имена первого
запуска. Изменение содержания, режима или алгоритма создаёт новый результат.

SQLite хранит и отчёт, и разобранные источники; Markdown и чат доступны после перезапуска.
UI и API должны использовать один `CACHE_DIR`, если запускаются отдельно. Внешние процессы
сериализуют создание анализов транзакцией, чтобы одновременные повторы не вызывали модель дважды.
Это рассчитано на локальную/небольшую командную установку, а не очередь массовых заданий.
Кэш не имеет автоматического срока удаления: он содержит тексты загруженных документов.
`USE_CACHE` больше не переключает новый интерфейс на непроверенный статический демо-отчёт.

Для установки именно проверенного окружения Python 3.11:

```powershell
uv venv --python 3.11 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.lock
.\.venv\Scripts\python.exe -m streamlit run ui/app.py --server.port 8503 --server.fileWatcherType poll
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m pytest -q
```

`requirements.txt` задаёт исходные зависимости; `requirements.lock` фиксирует версии проверенного
Windows/Python 3.11 окружения. Совместимость этого lock-файла с другими платформами отдельно не проверялась.

### Защита источников и обработка ошибок

- Файлы «до» и «после» сохраняются в разных подкаталогах; совпадающие имена безопасны.
- Ограничение на документ — 25 МБ. Пустые, повреждённые и неподдерживаемые файлы дают понятную ошибку.
- Верификатор требует полного вхождения цитаты с сохранением слов, регистра и пунктуации;
  допускаются только различия пробелов. Исключение — доказательство действительно пустого пункта.
- `repair` исправляет страницу существующей цитаты, но не заменяет выдуманный текст.
- Для пункта, продолжающегося на следующей странице PDF, хранится постраничный текст и определяется
  страница начала конкретной цитаты. DOCX всё ещё использует условные блоки, XLSX — номер листа.
- Очистка PDF удаляет совпадающие текстовые блоки в одной позиции и номера нижних колонтитулов;
  повторяющиеся обязанности в разных пунктах сохраняются. Нормализация для поиска/LLM отделена от цитат.
- При отсутствии раздела 5 или структуры отчёт явно сообщает о пропущенных проверках.
- Ошибки LLM оставляют выводы правил с предупреждением. При сбое embeddings весь анализ
  повторяется на TF-IDF; вектора разных алгоритмов не смешиваются. Такой результат тоже кэшируется.
- Markdown содержит цитаты для структурных изменений. Свободное непроверенное LLM-резюме
  не генерируется; источники ответа чата проверяются перед показом.
- Наличие дословной цитаты не доказывает правильность смыслового вывода. Экспертная оценка сохраняется.

### Сложные тестовые документы

```powershell
.\.venv\Scripts\python.exe -m app.generate_cases --out runs/generated --seed 42 --clauses-per-section 24
```

Команда создаёт `version_a.pdf`, `version_b.pdf`, обе DOCX-версии и `manifest.json` с описанием
намеренно внесённых изменений и SHA-256 файлов. По умолчанию PDF содержит по 24 страницы.
Одинаковые seed и параметры в одном окружении дают побайтно одинаковые документы.
Сценарии: разделение подразделения, потеря функции, удаление периодичности, дублирование,
двойное подчинение, самопроверка, отсутствующий адресат ссылки, пустой пункт и перенумерация приложения.
Manifest — описание тестовых изменений, а не обещание, что эвристики обнаружат каждый из них.

Тесты покрывают контрольный комплект, генератор, кэш и параллельные повторы, схемы и отказы LLM,
цитаты чата, продолжения страниц, одинаковые имена файлов, невалидный ввод и сценарии Streamlit.
Реальный OpenAI API в тестах не вызывается. Перед публичным развёртыванием остаются отдельными
задачами авторизация, ограничение запросов, очередь заданий и политика хранения документов.
`.dockerignore` исключает локальные ключи, окружение и результаты из Docker-контекста.

Контракт Structured Outputs реализован по [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs).
